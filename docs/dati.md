# Data and updates

Where the data comes from, how it is organised, how it is updated and how the repository is laid out.

## Regions and data

The data comes from Overpass (`natural=tree` and `natural=tree_stump`) and is divided by region. On opening no region is loaded: the map shows the countries, coloured from green to red according to their position in the ranking by share of trees with errors (grey if the data or counts are missing). Countries divided into regions (Italy, Poland, France, Spain, United Kingdom, Ireland, Austria) have the national boundary: tapping them shows their regions, coloured in the ranking only among themselves. The others (Bulgaria, Latvia) load directly. A region can also be chosen from the menu, where regions are grouped by country. "← All countries" returns to the overview. Direct address: `#region=lombardia`. On opening the map frames the largest group of nearby regions (Europe); distant regions, such as Japan, are reached from the menu.

* `data/regions/<region>.geojson.gz` – the trees of a region, with the checks already computed (compressed: the browser decompresses them). Nodes with `xmas:feature=tree` that are not `natural=tree` or `natural=tree_stump` are downloaded too, but kept in a separate `xmas` list of the file, outside the trees, counts and checks: they are only drawn as Christmas trees from 8 December to 6 January
* `data/regions/<region>.min.geojson.gz` – the reduced part of the same file: only trees with errors and monumental trees (`denotation=natural_monument`), the only ones visible below zoom 10. The site loads this first, which appears immediately, and meanwhile the full file, which for large regions (e.g. Lombardy, almost 400,000 trees) takes a few seconds; until it is ready the count says "loading all trees…". If the reduced file is missing, the site derives it from the full one
* `data/wikidata_items.json` – Wikidata cache of the items of `wikidata=*` (the individual trees): whether it is a taxon (has a scientific name, P225), coordinates (P625), image (P18), species (P10241), protection (P1435), Wikipedia articles, monumentaltrees.com ID (P9704) and whether it is an instance of monumental plant (P31 = Q811534). At every update of a region the script re-reads all the QIDs that the region uses, so corrections made on Wikidata reach the checks; if Wikidata does not respond the cached data stays, and the Wikidata checks do not trigger for QIDs never verified
* `data/wikidata_taxa.json` – Wikidata cache of species and genera (from `species:wikidata`, `genus:wikidata`, P10241 and, for the `species` values present in the data, the wiki list): whether it is a taxon, scientific name (P225), rank (P105), labels and aliases in Italian and English (for the common name); updated in the same way, except the aliases, which are requested only once per species; the items of the `species:wikipedia` articles are also there
* `data/wikipedia_qids.json` – cache of the `species:wikipedia` articles (`language:Title`) with the QID of the linked Wikidata item, requested from the Wikipedia API of that language following redirects (`null` if the article does not exist or has no item), for the hints on `species:wikidata` and `species`; re-read at every update
* `data/fotoshi.json` – author and licence of Fotoshi photos (`image:fotoshi`), read from each photo's page only once
* `data/url_status.json` – status of the links and Commons files already checked, with the date of the check
* `data/index.json` – list of available regions, number of trees, number of trees with errors (`errors`) and date of the latest data change
* `data/history.json` – history for the error trend and for the ranking movements: for each region, rows `[date, trees, trees with errors]`, one per day (if a region is updated more than once on the same day the last value stays, so the last row always matches `data/index.json`). It is written by `fetch_trees.py` at every update, even when the data does not change; dates up to 10/11/2026 were reconstructed from earlier versions of `data/index.json`
* `scripts/regions.json` – regions: name, English name (`name_en`, used when the site is in English), `group` (with `group_en`) (e.g. "Italia": regions with the same group appear together in the menu) and `group_rel` (the OSM relation of the country, for the national boundary on the map), ISO 3166-2 code (if it exists: the regions of England do not have one), OSM relation id (`rel`), approximate bbox and, if needed, `split` (initial tile subdivision levels: 0 for countries with few trees)
* `data/regions_boundaries.geojson` – simplified boundaries of the regions and of the countries divided into regions, to choose them on the map; generated by the "Update region boundaries" Action (from Nominatim). The Action downloads only the boundaries missing from the file (new regions or countries); tick "Download all the boundaries again" to replace them all, for example after a boundary or a `rel` in `regions.json` has changed (locally: `python scripts/update_boundaries.py --all`)

**Update**: from GitHub, Actions → "Update tree data" → Run workflow, choosing from the menu `all`, a group (`italia`, `polonia`, `regno-unito`, `francia`, `spagna` = all the regions of the country that are in `regions.json`) or a single region. To update several regions together, write them instead in the text field below the menu, separated by spaces or commas (e.g. `liguria veneto lettonia`): if the field is filled in, the menu is ignored. There are no automatic runs: the update starts only manually. If the download of a region fails its previous data stays; if the data does not change, the files are not modified.

Overpass server: if the secret `FAIRWAYMAPPER_KEY` is set (Settings → Secrets and variables → Actions), the script uses the [FairwayMapper](https://www.fairwaymapper.com/api/overpass) mirror first with that key (in the address `https://api.fairwaymapper.com/k/<key>/api/interpreter`, as in overpass-turbo; the secret can contain just the `fm_…` key or the whole address, and the key does not appear in the logs), at most 10 requests per minute; if the key is rejected or the limit is exhausted, it switches to the public servers (overpass-api.de and the others in `ENDPOINTS`). To avoid using up the key's quota, untick "Use FairwayMapper" when launching the Action. Locally the key is passed with the environment variable of the same name. Without a key only the public servers are used.

Locally: `python scripts/fetch_trees.py lombardia` (or `all`, `italia`, `liguria veneto`). A new region is added to `scripts/regions.json` and to the menu of `.github/workflows/update.yml`; then run "Update region boundaries" and "Update tree data".

Large regions are downloaded in pieces (tiles) and merged. The exact boundary is decided by the OSM administrative area; the bbox only serves to split the work, so if trees are missing at the edges of a region it is enough to enlarge it in `regions.json`.

## World map of monumental trees

[`monumental-trees/`](https://ivanbranco.github.io/tree-osm-qa/monumental-trees/) is a map to share without the QA part, with all the monumental trees (`denotation=natural_monument`) in the world and not only those in the tool's regions.

It also includes trees that are monumental according to other sources but do not have `denotation=natural_monument` on OSM ([issue #13](https://github.com/ivanbranco/tree-osm-qa/issues/13)): those that in the QA tool have the error on the monumental source (`ref:masaf`, `ref:rami`, monumentaltrees.com, `heritage:operator`, or the Wikidata item with P9704, instance of Q811534 or protection P1435). They are taken from the data of the QA tool's regions, so only in the covered regions, and are drawn like the other monumental trees; the card explains where the monumentality comes from in plain words ("Not marked as monumental on OSM, but it is according to MASAF and Wikidata"), with the tags involved in the pop-up on the ⓘ ("denotation=natural_monument is missing on OSM; sources: ref:masaf, wikidata=…"). In Italy it also includes the trees with the hint on the MASAF threshold (circumference at least equal to the MASAF indicative minimum circumference for the species, without `denotation=natural_monument` or `landmark` and without `ref:masaf`), except those with an error on the circumference: the card says "Not marked as monumental on OSM, but its circumference (4 m) reaches the minimum circumference set by MASAF for Wisteria sinensis (1.5 m)". Their number is in `implicit` in `data/world/index.json`; `masaf_size` counts those included only for the MASAF threshold.

It opens from the globe icon next to "Monumental tree" in the legend. On opening the map shows Europe. Below zoom 7 only one tree per area is shown and the others appear as you zoom in: for each zoom the world is divided into 48-pixel cells and in each cell one tree is shown, chosen in this order: first those with a photo on the card, then the largest (circumference measured or from the diameter, then height; measurements reported as errors do not count), then those with a name or `wikidata`. They are about 3,000 trees out of 90,000, in a separate file of less than 200 KB, and every zoom change takes a few tenths of a second; with all the trees even at low zoom the map stayed empty for several seconds (12 s at zoom 3 over Europe). From zoom 7 all are shown. The count below zoom 7 says "zoom in to see all", and the genus and species filter shows, below zoom 7, only the trees chosen for their areas. It has only the panel with the map title, "← Back to the QA tool", the genus and species filter, the count of trees in view and the date of the data; trees do not have the red outline for errors. The legend does not have the entries that cannot appear there (with errors, landmark, stump) and, in place of "Sacred tree", has "Monumental and sacred" with the half-yellow, half-light-blue outline. On the card, in place of the errors, there is only "⚠ see in the QA tool", which opens the tree in the tool, if the tree has errors and is in a region of the tool.

From zoom 7 the map also shows the trees of the MASAF list of monumental trees of Italy that are not yet on OpenStreetMap, with a dashed golden outline, as large as an OSM monumental tree without `diameter_crown` (crown of 5 m radius at real size, minimum 3 px; 6 m if the tree is also listed for crown width, criterion a2.3: `MASAF_CROWN_R` and `MASAF_CROWN_R_WIDE` in `scripts/fetch_world.py`), with the colour and (from zoom 16) the shape of the crown derived from the species as for OSM trees: `leaf_type` and `leaf_cycle` estimated from the wiki lists ([issue #17](https://github.com/ivanbranco/tree-osm-qa/issues/17)), and (from zoom 16) the trunk as for OSM trees, from the circumference in the list or, if missing, estimated from the height (lighter), and a card of its own: the data of the list (species without authors, place, type, height, circumference, criteria), the note "not on OpenStreetMap yet", the source citation required by the licence (CC BY 4.0) and the "Open on OpenStreetMap" link, which opens openstreetmap.org at zoom 19 on that point. A tree in the list is already on OSM if a node in Italy has its code in `ref:masaf` (leading zeros do not count), or if an OSM monumental tree of the same genus is within 25 m (`MASAF_NEAR` in `scripts/fetch_world.py`). The comparison is redone at every update of the map, so a tree added on OSM disappears from the dashed ones on the next run; the list data is in `scripts/masaf_trees.json`, written by `scripts/update_masaf.py`, and the result in `data/world/masaf.geojson.gz`. The genus and species filter also applies to these trees; the "Trees in view" count counts only OSM trees.

The "Completeness" tab of this map (see [The map](mappa.md)) has, at the top, the counter of the trees of the MASAF list already on OSM, "X of Y" with a bar, for Italy and, under "By region", for each Italian region. The counter appears only when the centre of the map is in Italy (inside the national boundary `g:Italia` of `data/regions_boundaries.geojson`, loaded when the tab is first opened; the boundary follows the coast, so with the centre on the sea the counter is hidden). It uses the same matching described above: `scripts/fetch_world.py` writes in `data/world/index.json` the number of listed trees (`masaf_total`), the trees not yet on OSM (`masaf`) and, for each region, `masaf_regions` (`{region slug: [already on OSM, listed]}`); the region is the last part of the MASAF code (the ISTAT code of the region; 21 and 22, the provinces of Bolzano and Trento, are counted together as Trentino-Alto Adige: `MASAF_REGIONS`). Tapping the counter highlights on the map, in magenta and at every zoom (also below zoom 7), the MASAF trees not yet on OSM; from far away they can also be clicked to open their card. With data written before these fields existed, the tab shows only how many trees are not yet on OSM, and says that the count will arrive with the next update of the map. Below the counter, the bars of the trees in view: Species, Height, Circumference and Photo, and Crown diameter apart, as optional; they count the OSM trees shown on the map (below zoom 7 only those chosen for their areas, and a note says so), including those that are monumental only according to other sources, not the MASAF trees not on OSM.

The page in the folder loads `index.html` setting the mode (`window.DENDROSM_MODE`, see `MODE` in the script): the code is one. The data is in `data/world/monumental.geojson.gz` (same checks as the tool; the `qa` property is the tool's region in which the tree falls, from the boundaries of `data/regions_boundaries.geojson`; `mz` is the zoom from which the tree appears, only for those visible below zoom 7), `data/world/monumental.low.geojson.gz` (only the trees with `mz`) and `data/world/index.json`. They are updated manually from the "Update monumental map" Action (`scripts/fetch_world.py`, locally `python scripts/fetch_world.py`). Links (`image`, `website`, `url`) are not rechecked: the broken-link check uses the tool's cache.

## Structure

* `scripts/fetch_trees.py` – downloads from Overpass, computes the checks, writes the data
* `scripts/fetch_world.py` – data of the world map (monumental trees of the whole world)
* `scripts/regions.json` – list of regions
* `scripts/update_boundaries.py` – downloads the region boundaries into `data/regions_boundaries.geojson`
* `scripts/update_reference_lists.py` – downloads the species and genus lists from the OSM wiki into `scripts/species_list.json` and `scripts/genus_list.json` (for genera also the common names of the `genus:xx` columns, under `names`), and the `denotation` values with the number of uses from Taginfo into `scripts/denotation_values.json`
* `scripts/species_limits.json` – per species: height and circumference limits, ratios used to estimate missing dimensions
* `scripts/update_masaf.py` – from the KML file of the MASAF list of monumental trees of Italy (downloaded manually from the [list page](https://www.masaf.gov.it/flex/cm/pages/ServeBLOB.php/L/IT/IDPagina/11260); about 30 MB, it does not go in the repository) writes `scripts/masaf_list.json`: each code with its status, listed or removed (reason and decree), for the check on removed trees; and `scripts/masaf_trees.json`, the listed trees with position, species, place, measurements and criteria, for the monumental trees map. It is rerun manually when a new version of the list comes out: `python scripts/update_masaf.py "Alberi monumentali d'Italia.kml"`. The loaded version is at the top of `scripts/masaf_list.json` (`"version"`, read from the KML description: currently "X Aggiornamento, D.Dir. n. 364243 del 24/07/2026"); if a new KML has the same version, the script says so
* `scripts/masaf_thresholds.json` – the MASAF indicative minimum circumferences per species (January 2020 table, from the PDF of [issue #1](https://github.com/ivanbranco/tree-osm-qa/issues/1)), transcribed by hand, for the hint on Italian trees that reach the threshold. The PDF does not go in the repository
* `scripts/whitelist.json` – exceptions to the checks: `species:wikidata` accepted per species (`wikidata_mismatch`), species not to be reported as misspelled (`species_typo`) and synonyms (`synonyms`: alternative name → name in the wiki list, for example `Crataegus × lavallei` → `Crataegus × lavalleei`; the alternative name counts as the one in the list in all checks) and monumental trees that really are very small (`small_monument`: node id → note)
* `.github/workflows/update.yml` – data update
* `.github/workflows/update-boundaries.yml` – boundaries update (manual only)
* `.github/workflows/update-species-list.yml` – "Update reference lists" Action: species, genera and `denotation` values (manual only)
* `.github/workflows/update-world.yml` – "Update monumental map" Action (manual only)
* `index.html` – the site
* `monumental-trees/index.html` – the world map of monumental trees (loads `index.html`); `monumental-trees/favicon.svg` and `favicon.png` are its icon, the same as the tool's but golden
* `taginfo.json` – the OSM tags used by the project, in the [Taginfo format](https://wiki.openstreetmap.org/wiki/Taginfo/Projects); if a tag is added or removed in `fetch_trees.py`, it must be updated here too

To publish, enable GitHub Pages from the `main` branch, root folder.
